# بوت متجر على تيليجرام بالعربية (Node.js)

متجر كامل داخل تيليجرام: العميل يتصفح الأقسام والمنتجات بالصور، ويضيف إلى السلة، ويكتب اسمه وجواله وعنوانه أو يرسل موقعه، فيصلك الطلب برقم وأزرار لتغيير حالته، ويصل العميل كل تحديث.

بلا أي مكتبة خارجية: Node.js 22 وقاعدة SQLite المدمجة فيه (`node:sqlite`). لا `npm install`، ولا خادم قاعدة بيانات.

شرح المشروع كاملاً، وكيف اختبرناه: **https://qeeid.com/telegram-store-bot-nodejs-source-code/**

## المزايا

**للعميل**
- أقسام ومنتجات بالصور والأسعار، وصفحات إن كثرت المنتجات
- سلة بأزرار ➕ و➖، والمجموع والتوصيل والإجمالي
- إتمام الطلب في خطوات: الاسم (بزر واحد من اسمه في تيليجرام)، والجوال (بزر «أرسل رقمي» أو كتابةً، حتى بالأرقام العربية)، والعنوان (كتابةً أو بزر «أرسل موقعي»)، وملاحظة
- رقم طلب، ورسالة عند كل تغيير في حالته، و«طلباتي» مع إلغاء الطلب ما دام جديداً

**لصاحب المتجر**
- تضيف المنتج بإرسال صورته وفي وصفها سطر واحد: `الاسم | السعر | القسم | الوصف | الكمية`
- إخفاء المنتج وإظهاره وحذفه بأزرار تحت بطاقته، و`/price` و`/stock` لتعديل السعر والكمية
- كل طلب يصلك برسالة فيها أزرار: قبول، شُحن، سُلّم، إلغاء. والرسالة نفسها تتحدث بالحالة
- لوحة `/admin`: طلبات اليوم ومبيعاته، والطلبات المفتوحة
- المخزون يُخصم عند التأكيد ويعود عند الإلغاء، والسعر يُثبَّت في الطلب فلا يتغير إن غيّرت سعر المنتج لاحقاً
- يدعم أكثر من صاحب للمتجر (`owners`)

## لا طلب يتكرر ولا تحديث يضيع

كل تحديث من تيليجرام يُعالج في معاملة SQLite واحدة تحفظ أثره (السلة، الطلب، المخزون) ورقمه معاً. والردود تُكتب في جدول «صادر» داخل المعاملة نفسها، ثم تُرسل بعدها. فإن انطفأ البوت في أي لحظة، عاد من حيث توقف تماماً.

في الاختبار: 2000 ضغطة «أضف إلى السلة» من 100 عميل، مع قتل البوت (`kill -9`) كل 0.4 ثانية (نحو 20 مرة): مجموع السلال 2000 بالضبط. والنسخة التي تحفظ رقم التحديث في الذاكرة فقط أضافت 900 إلى 1300 قطعة لم يطلبها أحد.

وإن تعطل تيليجرام (502) تبقى الرسالة في الصادر حتى تُرسل، وإن طلب التمهل (429) ينتظر المدة التي حددها.

## التشغيل

```bash
# Node.js 22.13 أو أحدث
git clone https://github.com/copissblog-alt/telegram-store-bot-ar.git
cd telegram-store-bot-ar
cp config.example.json config.json   # ثم عدّله
npm start
```

في `config.json`:
- `token`: من @BotFather
- `owners`: معرفك الرقمي في تيليجرام (من @userinfobot). يمكن أكثر من واحد
- `store_name` و`welcome` و`currency` و`delivery_fee` و`min_order` و`payment_note` (طريقة الدفع: عند الاستلام أو الآيبان)
- `utc_offset`: فرق توقيتك عن UTC (السعودية 3)

ثم أرسل للبوت صورة منتج وفي وصفها مثلاً:

```
عسل سدر 1 كيلو | 180 | العسل | من جبال الجنوب | 20
```

### على سيرفر (systemd)

ملف `deploy/store-bot.service` جاهز: يعيد تشغيل البوت تلقائياً، ويشغّله بمستخدم محدود لا يكتب إلا في مجلد `data`.

```bash
sudo useradd --system --home /opt/telegram-store-bot-ar storebot
sudo cp -r . /opt/telegram-store-bot-ar && sudo chown -R storebot: /opt/telegram-store-bot-ar
sudo cp deploy/store-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now store-bot
journalctl -u store-bot -f
```

البوت يستقبل بـ long polling، فلا يحتاج دوميناً ولا شهادة SSL ولا منفذاً مفتوحاً. ونسخة واحدة فقط تعمل بالتوكن نفسه (وإلا يرد تيليجرام بـ 409).

## الاختبارات

```bash
npm test
```

13 اختباراً مع خادم تيليجرام مزيف يعيد التحديثات حتى تُؤكَّد كما يفعل تيليجرام: الأسعار والجوال بالأرقام العربية، وإضافة المنتجات، والكتالوج، والسلة وحد المخزون، وإتمام الطلب كاملاً، والضغط المزدوج على «تأكيد»، وتثبيت السعر، وانتقالات الحالة وصلاحيات صاحب المتجر، والإلغاء وإرجاع المخزون، وهروب النصوص، وأخطاء 502 و429 و403، وقتل البوت في منتصف 100 طلب.

## الهيكل

```
bot.js            نقطة التشغيل
src/bot.js        حلقة الاستقبال والمعاملة وصندوق الصادر
src/handlers.js   منطق المتجر كله (متزامن، بلا شبكة)
src/db.js         الجداول
src/tg.js         عميل Bot API فوق fetch
src/ui.js         النصوص والأسعار والأزرار
tests/            الاختبارات وخادم تيليجرام المزيف
deploy/           ملف systemd
```
